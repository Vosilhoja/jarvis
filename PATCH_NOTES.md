# Патч: полнотекстовый поиск, Google Calendar, недельная сводка

## Как накатить
Распакуйте архив поверх вашего локального `jarvis\` (сохраняя структуру папок,
файлы заменяются). Затем поставьте новые зависимости:

```
pip install -r requirements.txt
```

(добавлены: python-docx, pypdf, google-auth, google-auth-oauthlib, google-api-python-client)

## Что нового

### 1. Полнотекстовый поиск по содержимому файлов
- Новый модуль `services/file_search.py`.
- Голосом/текстом: «найди документ, где упоминается договор с ООО Ромашка».
- Кнопка «📝 Поиск в файлах» в меню → 📁 Файлы.
- Ищет в .txt/.md/.csv/.log/.docx/.pdf в Рабочем столе/Документах/Загрузках
  (или в указанной папке), с таймаутом ~25с и лимитом размера файла 15 МБ —
  не зависнет на реальном диске.

### 2. Google Calendar
- Новый модуль `services/calendar_client.py`.
- Голосом/текстом: «что у меня сегодня по плану», «что у меня на неделе».
- Кнопка «📅 Календарь сегодня» в меню → 🖥 Система.
- **Требует настройки от вас** (агент не может сделать это сам):
  1. https://console.cloud.google.com/ → создать проект.
  2. APIs & Services → Library → включить **Google Calendar API**.
  3. OAuth consent screen → External → добавить себя в Test users.
  4. Credentials → Create Credentials → OAuth client ID → **Desktop app**.
  5. Скачать JSON, положить в корень проекта как `credentials.json`
     (или задать свой путь через `.env`: `GOOGLE_CALENDAR_CREDENTIALS_PATH=...`).
  6. Первый вызов откроет браузер на этом же ПК для входа в Google — один раз.
     Токен закэшируется в `data/google_calendar_token.json` и будет обновляться
     сам.
- Если `credentials.json` ещё не создан — бот пришлёт пошаговую инструкцию
  вместо ошибки.

### 3. Недельная сводка статистики
- `services/usage_stats.py::get_weekly_report()` теперь включает топ сайтов
  (раньше — только топ приложений и простой).
- **Исправлен баг**: `record_idle_sample()` существовал, но нигде не
  вызывался — простой ПК всегда показывался как «недостаточно данных».
  Теперь пишется каждый цикл `scheduler.py` (раз в
  `BACKGROUND_CHECK_INTERVAL_SEC`, по умолчанию 120с).
- Кнопка «📈 Недельная сводка» в меню → 🖥 Система.
- Автоматическая рассылка раз в неделю (по умолчанию понедельник 9:00,
  настраивается в `.env`: `WEEKLY_REPORT_WEEKDAY`/`WEEKLY_REPORT_HOUR`,
  0=понедельник).

## Проверка на моей стороне
- `py_compile` — все изменённые/новые файлы компилируются.
- AST-проверка top-level def/class до и после правок — ничего не потерялось,
  количество совпадает с ожидаемым (+1 функция в file_actions.py, +4 модели
  параметров в intent_schema.py, остальные файлы — без изменения числа
  функций).
- Реальная (не только синтаксическая) проверка через pydantic: все 4 новых
  intent'а валидируются, есть в `INTENT_REGISTRY`, попадают в промпт для
  Gemini (`generate_intents_documentation()`), имеют risk-level SAFE в
  `security/risk.py`.
- Сверка `core/executor.py::INTENT_HANDLER_MAP` (58 хендлеров) против
  экспортов `core/execution/__init__.py` (59 имён) — все ссылки разрешаются,
  ничего не отсутствует.
- Рантайм на Windows (pyvda/win32api/WMI/реальный Google OAuth) я тестировать
  не могу — только статическая проверка, как указано в моём формате сдачи
  работы.
