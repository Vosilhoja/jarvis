Распакуйте поверх `C:\Users\vosil\Desktop\jarvis\` (это уже ВТОРОЙ патч поверх
первого — структура та же). Затем:

```

```

(добавилась только одна новая: `speedtest-cli`)

Остановите watchdog.py + main.py, перезапустите `py watchdog.py`.

## Что исправлено (из таблицы рисков)

- **#3 pynput/AV** — новая настройка `.env`: `SECURITY_GUARD_KEYBOARD_DETECTION=false`
  полностью отключает keyboard-хук в режиме охраны, если антивирус будет ругаться
  (по умолчанию `true`, поведение не меняется).
- **#4 обрезка папки без предупреждения** — лимит поднят с 5000 до 20000 объектов,
  и если всё равно упёрлись в лимит — теперь есть явное предупреждение в ответе,
  а не тихая обрезка.
- **#5 "Скрыть все окна" сворачивал Telegram Desktop** — новая настройка `.env`:
  `HIDE_WINDOWS_EXCLUDE_PROCESSES=telegram.exe` (по умолчанию уже включает
  Telegram) — эти процессы никогда не сворачиваются.
- **#6 календарь/погода в брифинге** — проверил: `get_today_events()` и
  `get_weather_forecast()` уже сами никогда не бросают исключения и возвращают
  осмысленный текст (включая инструкцию по настройке OAuth, если токен не найден) —
  реальных изменений не потребовалось, только подтверждено тестом.
- **#7 тест скорости 403 Forbidden** — теперь основной метод через `speedtest-cli`
  (реальный выбор ближайшего сервера), старый Cloudflare-хак остался как fallback,
  если speedtest-cli недоступен.

## Новые фичи

- **Whitelist процессов для "зависших окон"** (`config.py::HUNG_APP_WHITELIST`) —
  по умолчанию исключены тяжёлые IDE/движки (devenv, VS Code, PyCharm, IDEA, Unity,
  Unreal, Photoshop, Premiere, After Effects, Blender, DaVinci Resolve). Список
  настраивается через `.env`.
- **Диагностика Wi-Fi во времени** (`services/wifi_monitor.py`) — в фоне каждые
  ~2 минуты (тот же цикл, что и остальной мониторинг) сэмплируется уровень
  сигнала текущей Wi-Fi сети, копится история. Кнопка «📶 Диагностика сигнала» в
  меню «Сеть» показывает отчёт за 24 часа: средний/мин/макс сигнал, число разрывов
  связи — а не разовый снимок, как раньше. Данные появятся не сразу, а через
  несколько циклов после перезапуска.

## Проверено (Linux-песочница, статически + функциональные тесты через моки)
- whitelist зависших окон: Unity/VS Code отфильтрованы, обычное окно — нет
- SECURITY_GUARD_KEYBOARD_DETECTION=false реально не даёт слушателю запуститься
- HIDE_WINDOWS_EXCLUDE_PROCESSES реально исключает Telegram.exe из сворачивания
- лимит сканирования папки: явное предупреждение при превышении (тест на 22500 файлах)
- speed_test(): основной путь speedtest-cli + fallback на Cloudflare при сбое
- wifi_monitor: парсинг реального формата `netsh wlan show interfaces`,
  запись/чтение истории, агрегация отчёта с подсчётом разрывов связи
- полная кнопка «📶 Диагностика сигнала» протестирована через реальный
  `handle_reply_keyboard()` от начала до конца

Реальный Windows-рантайм (в т.ч. AV-реакция на pynput, настоящий netsh на живой
Wi-Fi-карте) не тестировался — недоступно в Linux-контейнере.
